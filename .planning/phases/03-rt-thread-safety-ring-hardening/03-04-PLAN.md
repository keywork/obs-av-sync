<objective>
Emit a rate-limited `LOG_WARNING` to the OBS log whenever an audio chunk is skipped due to exceeding `downmix_capacity`, making previously-silent frame loss visible during a live show.
</objective>

<must_haves>
- Oversize detection uses `data->downmix_capacity` (heap field from Plan 1), not the removed `AV_SYNC_DOWNMIX_SCRATCH` constant
- Warning log fires at most once per `AV_SYNC_DIAG_LOG_INTERVAL_NS` window (5 s), reusing the existing `window_start_ns` rollup gate
- Warning message includes `oversize_skips` count, source name, and `data->downmix_capacity`
- Warning uses `obs_log(LOG_WARNING, ...)` (not `LOG_INFO`)
- The warning fires inside the existing rollup log block, not as a separate timer
</must_haves>

<task id="T02">
<title>Add rate-limited oversize warning inside the existing rollup log gate</title>
<read_first>
- src/av_sync_filter.c (the rollup log block, starting at `if (ts - data->window_start_ns >= AV_SYNC_DIAG_LOG_INTERVAL_NS)`)
</read_first>
<action>
Inside the existing rollup block (the `if (ts - data->window_start_ns >= AV_SYNC_DIAG_LOG_INTERVAL_NS)` branch), add the oversize warning **before** the existing `obs_log(LOG_INFO, "passthrough rollup ...")` call.

The block should be augmented as follows. The new lines are marked with `/* NEW */`:

```c
    if (ts - data->window_start_ns >= AV_SYNC_DIAG_LOG_INTERVAL_NS) {
        /* NEW: emit a warning if any oversize chunks were skipped this window. */
        if (data->oversize_skips > 0) {
            obs_source_t *parent_warn = data->source ? obs_filter_get_parent(data->source) : NULL;
            const char *warn_name = parent_warn ? obs_source_get_name(parent_warn) : "(unknown)";
            obs_log(LOG_WARNING,
                    "oversize chunk skips=%" PRIu64 " on '%s' (downmix capacity=%zu); data lost",
                    data->oversize_skips, warn_name, data->downmix_capacity);
        }

        const uint64_t elapsed_ns = ts - data->first_timestamp_ns;
        /* ... rest of rollup block unchanged ... */
```

Note on the warning: `frames=` is intentionally absent — `audio->frames` at the rollup point reflects the *current* callback's frame count, NOT the oversize chunk that was skipped. Reporting it would produce misleading diagnostics. The `oversize_skips` counter and `downmix_capacity` are both accurate and sufficient.

The complete updated rollup block should read:

```c
    if (ts - data->window_start_ns >= AV_SYNC_DIAG_LOG_INTERVAL_NS) {
        if (data->oversize_skips > 0) {
            obs_source_t *parent_warn = data->source ? obs_filter_get_parent(data->source) : NULL;
            const char *warn_name = parent_warn ? obs_source_get_name(parent_warn) : "(unknown)";
            obs_log(LOG_WARNING,
                    "oversize chunk skips=%" PRIu64 " on '%s' (downmix capacity=%zu); data lost",
                    data->oversize_skips, warn_name, data->downmix_capacity);
        }
        const uint64_t elapsed_ns = ts - data->first_timestamp_ns;
        const double elapsed_s = (double)elapsed_ns / 1.0e9;
        const double eff_rate = elapsed_s > 0.0 ? (double)data->total_frames / elapsed_s : 0.0;
        av_sync_ring_stats_t rs = {0};
        av_sync_ring_get_stats(data->ring, &rs);
        const double fill_pct = rs.capacity > 0 ? (100.0 * (double)rs.filled / (double)rs.capacity) : 0.0;
        obs_log(LOG_INFO,
                "passthrough rollup cb=%" PRIu64 " t=%.1fs frames=%" PRIu64
                " eff=%.1fHz nominal=%u max_gap=%.2fms ring=%zu/%zu (%.0f%%) written=%" PRIu64
                " skips=%" PRIu64,
                data->callback_count, elapsed_s, data->total_frames, eff_rate,
                data->sample_rate, (double)data->window_max_gap_ns / 1.0e6, rs.filled,
                rs.capacity, fill_pct, rs.total_written, data->oversize_skips);
        data->window_start_ns = ts;
        data->window_max_gap_ns = 0;
    }
```
</action>
<acceptance_criteria>
- `src/av_sync_filter.c` contains `obs_log(LOG_WARNING,`
- `src/av_sync_filter.c` contains `"oversize chunk skips=%" PRIu64 " on '%s' (downmix capacity=%zu); data lost"`
- `src/av_sync_filter.c` does NOT contain `frames=%u` in the LOG_WARNING format string
- `src/av_sync_filter.c` contains `data->oversize_skips > 0` inside the rollup gate block
- The `obs_log(LOG_WARNING` line appears BEFORE the `obs_log(LOG_INFO, "passthrough rollup` line in the file
</acceptance_criteria>
</task>

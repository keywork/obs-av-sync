   - Analysis window: 4 s

   - Accuracy: < 1 ms synthetic, ≤ 20 ms live production residual
   - Failure mode: requires non-silent audio on both reference and source
2. **ONVIF complement value proposition** — scenarios where ONVIF would add value:
   - Silent audio periods (no correlation possible)
   - CPU load reduction (skip GCC-PHAT when clock sync is trusted)
   - Long-term drift tracking without continuous audio analysis
   - Initial offset estimation before audio convergence
3. **Overlap and redundancy** — scenarios where ONVIF and GCC-PHAT measure the same thing
4. A decision matrix: for each production scenario (normal show, silent camera, high CPU load, startup), which method is preferred
5. Conclude whether ONVIF is a *complement* (adds capability), *substitute* (replaces), or *redundant* (adds nothing new)
</action>

<action>
Write two final sections:

**`## Verdict & Rationale`**
1. State the verdict clearly: **Adopt**, **Defer**, or **Skip**
2. If **Adopt**:
   - State which ONVIF method is recommended
   - State the chosen integration path (direct or external)
   - Summarize the evidence: accuracy ≤ 5 ms, feasible integration, clear benefit over GCC-PHAT alone
3. If **Defer**:
   - State the specific blocker(s): complexity, camera variability, OBS API limitations, or insufficient benefit/cost ratio
   - State the unblock condition(s): what would change the verdict to Adopt
   - Estimate when to revisit (e.g., "after Phase 8 UI is complete" or "if OBS adds Media Source timing API")
4. If **Skip**:
   - State the definitive blocker: accuracy > 5 ms, technically infeasible, or no accessible timing metadata
   - Document the blocker so the decision does not need to be re-researched

**`## Revisit Criteria`**
1. List specific, observable conditions under which the verdict should be re-evaluated
2. Each criterion must be falsifiable (e.g., "OBS adds `obs_source_get_audio_timestamp` API" — can be checked in future OBS release notes)
3. Include a recommended review trigger (e.g., "revisit at Milestone 2 planning" or "revisit if camera fleet changes")
</action>

# Plan 04-01: Vendor PFFFT via FetchContent

## Objective
Add the hayguen/pffft library as a CMake FetchContent dependency, pin it to a
stable version, link it to the plugin target, and verify a clean build.

## Background
PFFFT (Pretty Fast FFT) is a BSD-like-licensed SIMD-accelerated FFT library.
The hayguen fork provides a CMakeLists.txt that exports a `pffft` target.
Using CMake FetchContent avoids git submodules and keeps the version pin explicit
in our build file.  PFFFT is compatible with GPL-2.0-or-later, so there is no
licence pollution.

## Tasks

### T01: Include FetchContent module
**Action:** Add `include(FetchContent)` to the root `CMakeLists.txt` before the
`add_library(${CMAKE_PROJECT_NAME} MODULE)` line.
**File:** `CMakeLists.txt`
**Verification:** `grep -n "include(FetchContent)" CMakeLists.txt` returns a
non-empty result.

### T02: Declare and make PFFFT available
**Action:** Insert a `FetchContent_Declare(pffft ...)` / `FetchContent_MakeAvailable(pffft)`
block immediately after the `include(FetchContent)` line.
Use the following parameters:
- `GIT_REPOSITORY https://github.com/hayguen/pffft.git`
- `GIT_TAG        08f5ed2618ac06d7dcc83d209d7253dc215274d5`  (stable commit from research; v1.0.1 tag is acceptable if available)

**File:** `CMakeLists.txt`
**Verification:** `cmake --preset windows-x64` (or the relevant local preset)
configures without FetchContent errors.

### T03: Link PFFFT to the plugin target
**Action:** Append `target_link_libraries(${CMAKE_PROJECT_NAME} PRIVATE pffft)`
after the existing `target_link_libraries(${CMAKE_PROJECT_NAME} PRIVATE OBS::libobs)`
line (and after any frontend-api / Qt blocks).
**File:** `CMakeLists.txt`
**Verification:** The plugin target links `pffft`; `cmake --build` succeeds.

### T04: Document version pin and licence
**Action:** Add a comment block directly above the `FetchContent_Declare` call:
```cmake
# PFFFT — BSD-like licence, compatible with GPL-2.0-or-later
# Version pin: commit 08f5ed2618ac06d7dcc83d209d7253dc215274d5 (hayguen fork)
# Fallback for offline builds: set FETCHCONTENT_SOURCE_DIR_PFFFT to a local clone
```
**File:** `CMakeLists.txt`
**Verification:** The comment block is present and readable in the file.

### T05: Build verification
**Action:** Run the CMake configure + build preset for the local platform:
```sh
cmake --preset windows-x64
cmake --build --preset windows-x64
```
(or `macos`, `ubuntu-x86_64` as appropriate).
**File:** N/A (build step)
**Verification:** Build completes with **zero errors**.  A single `#include "pffft.h"`
in a temporary source file must be resolvable.

## Acceptance Criteria
- [ ] `CMakeLists.txt` contains `FetchContent_Declare(pffft`
- [ ] `CMakeLists.txt` contains `target_link_libraries(... PRIVATE pffft)`
- [ ] `cmake --build` produces zero errors on the local platform
- [ ] PFFFT headers are findable by `#include "pffft.h"` without extra `include_directories`
- [ ] A comment above the FetchContent block documents the version pin, licence, and offline fallback

## Notes
- **Offline builds:** If FetchContent fails because the machine is offline, the
  builder can set `-DFETCHCONTENT_SOURCE_DIR_PFFFT=/path/to/local/pffft`.
- **CI caching:** FetchContent downloads are cached automatically by GitHub Actions
  via the `actions/cache` step already present in the template workflows.
- **Real vs complex FFT:** PFFFT’s real-FFT packed format is tricky; Phase 4 will
  use `PFFFT_COMPLEX` (see 04-02 plan).  The vendoring step does not need to
  choose a transform type.
- **No C++ standard change required:** PFFFT is plain C; linking it into our
  mixed C/C++ target is transparent.

## Risks
| Risk | Mitigation |
|---|---|
| FetchContent fails offline | Document `FETCHCONTENT_SOURCE_DIR_PFFFT` override |
| hayguen/pffft tag moves or disappears | Pin an exact commit hash, not a floating tag |
| C++ compilation breaks C11 atomics on MSVC | CI build matrix catches it; this plan only adds a C library |

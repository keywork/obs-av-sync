# Plan 04-02: Implement gcc_phat.cpp

## Objective
Implement the GCC-PHAT (Generalized Cross-Correlation with Phase Transform)
pipeline in a new C++ translation unit, exposing a C-compatible interface so that
existing C code (`av_sync_filter.c`) can call it without modification.

## Background
GCC-PHAT is the core delay-estimation algorithm for obs-av-sync.  Given two
aligned audio buffers (reference and target), it returns a sub-sample-accurate
time offset and a confidence score.  The implementation uses PFFFT in complex
mode (`PFFFT_COMPLEX`) because the packed real-FFT output format is error-prone.

### T02: Create `src/gcc_phat.cpp` — GCC-PHAT pipeline
**Action:** Implement `estimate_offset` in `src/gcc_phat.cpp`.

Required includes at the top of the file:
```cpp
#include <algorithm>
#include <complex>
#include <cmath>
#include <cstddef>
#include <cstdint>
#include "pffft.h"
#include "gcc_phat.h"
```

The function must perform the following steps in order:

1. **Determine FFT size:** `FFT_SIZE` = next power of two ≥ `n_samples`.
2. **Allocate aligned buffers:** Use `pffft_aligned_malloc` for:
   - `ref_complex`   (2 × FFT_SIZE floats, interleaved real/imag)
   - `tgt_complex`   (2 × FFT_SIZE floats, interleaved real/imag)
   - `ref_spec`      (2 × FFT_SIZE floats)
   - `tgt_spec`      (2 × FFT_SIZE floats)
   - `cross_ph`      (2 × FFT_SIZE floats)
   - `gcc`           (2 × FFT_SIZE floats)
   - `work`          (2 × FFT_SIZE floats, PFFFT scratch area)
3. **Create PFFFT setup:** `pffft_new_setup(FFT_SIZE, PFFFT_COMPLEX)`.
4. **Copy + zero-pad:** For each buffer, map real samples to complex:
   ```cpp
   ref_complex[2*i]     = ref[i];
   ref_complex[2*i + 1] = 0.0f;   // imaginary part
   ```
   for `i = 0 .. n_samples-1`, and zero the remainder from `n_samples` to `FFT_SIZE`.
   Repeat for `tgt_complex`.
5. **Forward FFT both signals:**
   ```cpp
   pffft_transform(setup, ref_complex, ref_spec, work, PFFFT_FORWARD);
   pffft_transform(setup, tgt_complex, tgt_spec, work, PFFFT_FORWARD);
   ```
6. **Cross-spectrum (element-wise):**
   `X_cross = X_ref * conj(X_tgt)` using `std::complex<float>` arithmetic.
7. **PHAT whitening:**
   For each bin compute `mag = std::abs(X_cross)`.
   If `mag > 1e-12f`, set `X_ph = X_cross / mag`; otherwise set `X_ph = 0`.
8. **Inverse FFT:**
   `pffft_transform(setup, cross_ph, gcc, work, PFFFT_BACKWARD);`
9. **Normalise:** Divide every element of `gcc` by `FFT_SIZE` (PFFFT does not
   normalise inverse transforms).
10. **Peak pick:** Search the complex output for the maximum magnitude using
    stride-2 indexing:
    ```cpp
    float max_mag = 0.0f;
    int peak_bin = 0;
    for (int k = 0; k < FFT_SIZE; ++k) {
        float mag = std::hypot(gcc[2*k], gcc[2*k + 1]);
        if (mag > max_mag) {
            max_mag = mag;
            peak_bin = k;
        }
    }
    ```
11. **Parabolic interpolation:** Use the real parts (or magnitudes) at stride-2:
    ```cpp
    float ym1 = gcc[2 * ((peak_bin - 1 + FFT_SIZE) % FFT_SIZE)];
    float y0  = gcc[2 * peak_bin];
    float yp1 = gcc[2 * ((peak_bin + 1) % FFT_SIZE)];
    float denom = 2.0f * (ym1 - 2.0f * y0 + yp1);
    float p = 0.0f;
    if (std::fabs(denom) > 1e-12f)
        p = (ym1 - yp1) / denom;
    ```
    Add `p` to `peak_bin` as a fractional correction.
12. **Convert to delay:**
    ```cpp
    float delay_samples = (peak_bin > FFT_SIZE / 2)
                          ? (peak_bin - FFT_SIZE)
                          : peak_bin;
    delay_samples += p;
    result.offset_ns = delay_samples * 1e9f / static_cast<float>(sample_rate);
    ```
13. **Confidence (PSR):**
    - `peak = std::fabs(gcc[peak_bin])`
    - Compute RMS sidelobe magnitude (`sqrt(mean(|gcc[k]|^2))` excluding
      `peak_bin ± 2` bins).
    - `PSR = peak / sidelobe_rms`
    - `result.confidence = PSR;`
14. **Clean up:**
    - `pffft_destroy_setup(setup);`
    - `pffft_aligned_free` for every buffer allocated in step 2.

**File:** `src/gcc_phat.cpp`
**Verification:** Compiles with zero errors and zero warnings at `/W4` (MSVC) or
`-Wall -Wextra` (GCC/Clang).

## Notes
- **Complex FFT mode:** We deliberately use `PFFFT_COMPLEX` (interleaved real/imag)
  even for real signals because PFFFT’s real-FFT packed format is confusing and
  error-prone.  The 2× memory overhead (≈ 1 MB per 128k buffer) is acceptable.
- **Hann window:** The pipeline in this plan performs raw rectangular-window
  correlation.  A Hann window can be added later (Phase 6) if side-lobe suppression
  becomes necessary; it is not required to meet the ±1 ms accuracy target at
  SNR ≥ 10 dB.
- **C++ standard:** No explicit `CMAKE_CXX_STANDARD` is needed.  Modern compilers
  default to C++17, which is sufficient for `std::complex<float>` and `<cmath>`.
- **Thread safety:** `estimate_offset` is stateless (all allocations are local).
  It is safe to call concurrently from multiple analysis threads, provided each
  call uses its own buffers.
- **No OBS API usage:** This file is pure DSP; it does not include `obs.h` or
  call any OBS functions.  This keeps it testable in isolation.
- **`M_PI` portability:** `M_PI` is not defined by the C or C++ standards and is
  unavailable on MSVC.  Use `std::acos(-1.0f)` instead for cross-platform
  portability.

## Risks
| Risk | Mitigation |
|---|---|
| Parabolic interpolation unstable at low SNR | Denominator guard falls back to integer peak |
| PFFFT complex FFT slower than real FFT | Benchmark in Phase 6; real-FFT path is a future optimisation |
| C++ compilation breaks C11 atomics on MSVC | CI build matrix catches it; C and CXX flags are independent |
| `pffft_aligned_malloc` unavailable on some platforms | The hayguen fork exports it; if missing, use platform `aligned_alloc` |
